# Экосистема: симуляция «растения — кролики — волки»

Java-приложение с графическим интерфейсом (Swing), моделирующее простую
пищевую цепочку на двумерном поле (сетке). На поле живут три вида агентов —
**растения**, **кролики** и **волки** — которые едят, двигаются, тратят и
накапливают энергию, размножаются и умирают. Симуляция запускается через
GUI и может выполняться пошагово или в непрерывном цикле с регулируемой
скоростью.

---

## 1. Общая идея

Мир — это квадратная сетка `range × range` (по умолчанию 30×30). Каждая
клетка либо пуста, либо занята одним живым агентом. На каждом «шаге»
(tick) симуляции все живые агенты по очереди выполняют своё действие
(`act()`): двигаются, едят, тратят энергию и, если накопили её достаточно,
размножаются.

Пищевая цепочка:

```
Растение → Кролик → Волк
```

- **Растения** не двигаются и не едят — они просто накапливают энергию
  каждый ход и размножаются, когда её становится слишком много.
- **Кролики** едят растения, избегают волков, размножаются при достатке
  энергии.
- **Волки** едят кроликов, размножаются при достатке энергии, а если не
  находят добычи — просто голодают.

Умирает агент, когда его энергия опускается до нуля или ниже, либо когда
его съедают.

## 2. Структура проекта

```
models/
  Agent.java        — абстрактный базовый класс для всех агентов
  Environment.java   — «мир»: сетка, инициализация, цикл симуляции, статистика
  Plant.java         — растение
  Rabbit.java        — кролик (травоядное)
  Wolf.java          — волк (хищник)

gui/
  Sprites.java        — загрузка и кэширование картинок (PNG) агентов
  WorldPanel.java      — отрисовка сетки мира на экране
  SimulationFrame.java — главное окно, кнопки управления, игровой цикл

Main.java — точка входа, создаёт мир и окно
```

### Разделение ответственности

- **`models`** — вся логика симуляции, полностью независима от GUI (её
  можно было бы гонять и в консоли — в `Environment` для этого остались
  методы `show()`, `showOne()`, `showMore()`).
- **`gui`** — только отображение и управление: рисует то, что происходит в
  `Environment`, и дёргает `world.step()` по таймеру или по кнопке.

## 3. `models.Agent` — базовый класс агента

Абстрактный класс, от которого наследуются `Plant`, `Rabbit`, `Wolf`. Хранит
общие для всех агентов поля и реализует общую механику: движение, поедание
добычи, размножение и смерть. Специфичное для каждого вида поведение
(«что делать на этом ходу») описывается в наследниках через `act()`.

### Поля

| Поле | Назначение |
|---|---|
| `x, y` | координаты агента на сетке |
| `energy` | текущий запас энергии; при `<= 0` агент умирает |
| `max_nrg` | не используется напрямую в текущей логике (оставлено как задел) |
| `alive` | жив ли агент |
| `field` | ссылка на общую сетку `Agent[][]`, куда агент сам себя вписывает/удаляет |
| `type` | строковый тип (`"Plant"`, `"Rabbit"`, `"Wolf"`) — используется для сравнений и статистики |
| `preyType` | тип добычи (у кролика — `"Plant"`, у волка — `"Rabbit"`, у растения — `null`) |
| `range` | размер стороны сетки, нужен для проверки границ |

### Абстрактные методы (реализуются в наследниках)

- **`act()`** — что агент делает за один ход симуляции. Главная точка
  расхождения поведения между видами.
- **`look(String type)`** — вернуть список координат клеток в радиусе
  видимости, где встречен агент указанного типа.
- **`near(List<int[]> found)`** — из найденных кандидатов выбрать
  ближайшего (по евклидову расстоянию через `len()`).
- **`createChild(int cx, int cy, int childEnergy)`** — создать потомка
  нужного подкласса в клетке `(cx, cy)` с заданной энергией.

### Общие методы

**`move(int dx, int dy)`** — переместиться в направлении `(dx, dy)`.
Работает не «в лоб», а с запасными вариантами, чтобы агент не застревал:

1. Определяется «главная» ось движения (та, по которой смещение больше) и
   «боковая».
2. Строится список кандидатов-направлений в порядке приоритета: главная
   ось → боковая ось → диагональ (главная+боковая) → противоположное
   направление.
3. Перебираются кандидаты по очереди:
   - если соседняя клетка пуста — агент переходит туда и тратит 1 энергии;
   - если в клетке жива добыча агента (`preyType` совпадает с типом
     соседа) — вызывается `eat()`;
   - если клетка занята кем-то другим — кандидат пропускается.
4. Если все варианты заняты — агент остаётся на месте и энергию не тратит.

Это позволяет агенту, например, «обойти» соседа сбоку, если прямой путь к
цели заблокирован, вместо того чтобы застревать в бесконечном цикле
«шаг туда-сюда».

**`eat(Agent prey)`** — стандартное поедание добычи: хищник получает
энергию жертвы, занимает её клетку, жертва умирает, у хищника списывается
1 энергии за «прыжок». Переопределяется в `Wolf` (см. ниже — там ещё
добавляется бонус за охоту).

**`die()`** — помечает агента мёртвым (`alive = false`) и убирает его со
своей клетки поля (если клетка всё ещё принадлежит именно ему — защита от
случая, когда клетку уже занял кто-то другой).

**`div()`** — размножение агента:

1. Проверяется `canDivide()` — видо-специфичное ограничение (лимит
   популяции, плотность и т.д.). Если нельзя — выходим.
2. Ищутся свободные соседние клетки (4-связность: вверх/вниз/влево/вправо).
3. Если свободных нет — размножение не происходит.
4. Из свободных клеток случайно выбирается одна.
5. Потомку передаётся половина энергии родителя плюс буфер
   (`CHILD_BUFFER = 4`), чтобы потомок не рождался «полумёртвым». При этом
   родитель гарантированно сохраняет хотя бы 1 энергии.
6. Через `createChild()` в выбранную клетку помещается новый агент нужного
   подкласса.

Метод `div()` переопределён в `Plant` — у растений другая логика (см.
ниже): они размножаются в *любую* свободную клетку на карте, а не только
в соседнюю, чтобы не образовывались локальные «заросли», истощающие
местную почву.

**`canDivide()`** — базовая реализация всегда возвращает `true`;
переопределяется в каждом виде своим лимитом.

**`len(int dx, int dy)`** — вспомогательный метод, евклидово расстояние от
текущей позиции агента до точки `(dx, dy)`. Используется в `near()` для
выбора ближайшей цели.

## 4. `models.Plant` — растение

Самый простой агент: не двигается, не охотится, только копит энергию и
делится.

- **`act()`**: `energy++` каждый ход; если энергия превысила
  `currentMax` (случайное стартовое значение из диапазона 8–12,
  подбирается один раз при загрузке класса) — вызывается `div()`.
- **`div()` (переопределён)**: в отличие от базового `Agent.div()`, ищет
  свободную клетку *по всему полю*, а не только рядом с собой. Это
  сделано специально: если бы растения размножались только по соседству,
  локальные скопления растений быстро «выедали» бы всё вокруг себя и
  дальше расти было бы некуда, а другие участки поля оставались пустыми.
  Потомку передаётся половина накопленной энергии родителя.
- **`canDivide()` (переопределён)**: считает долю клеток поля, занятых
  живыми растениями, и разрешает размножение только пока плотность
  растений меньше `max_destiny = 0.3` (30% поля). Это ограничивает
  бесконтрольный рост растений и не даёт им занять всю карту.
- `look()` и `near()` возвращают пустые значения — растениям не нужно
  никого искать.

## 5. `models.Rabbit` — кролик (травоядное)

Питается растениями, убегает от волков, умеет размножаться при накоплении
энергии.

Поля: `visRange = 3` (радиус видимости), `currentMax` (лимит популяции,
по умолчанию 200, динамически меняется из `Environment`), 
`currentDivideThreshold` (порог энергии для размножения, по умолчанию 18,
тоже динамический).

**`act()`** — порядок приоритетов на каждом ходу:

1. **Угроза.** Ищутся волки в радиусе видимости (`look("Wolf")`). Если
   найдены — выбирается ближайший (`near()`) и кролик двигается *в
   противоположную от него сторону* (`move(x - t[0], y - t[1])`).
2. **Еда.** Если угроз нет — ищутся растения (`look("Plant")`). Если
   найдены — кролик двигается к ближайшему. Если растение оказывается
   в соседней клетке, `move()` съест его автоматически (через
   `preyType == "Plant"`).
3. **Блуждание.** Если ни угроз, ни еды не видно — кролик делает случайный
   шаг в одном из 4 направлений.

После любого из вариантов вызывается `finishTurn()`.

**`finishTurn()`** — общая пост-обработка хода: если энергия упала до 0 или
ниже — кролик умирает; если энергия достигла `currentDivideThreshold` —
кролик размножается (`div()`).

**`look(String type)`** — перебирает все клетки в квадрате
`[x-visRange, x+visRange] × [y-visRange, y+visRange]` (с проверкой границ
через `inBounds()`) и собирает координаты живых агентов нужного типа.

**`near(List<int[]> found)`** — выбирает из найденных кандидатов
ближайшего по евклидовому расстоянию.

**`canDivide()` (переопределён)** — пересчитывает текущее число живых
кроликов на поле и разрешает размножение, только если оно меньше
`currentMax`.

**`createChild()`** — создаёт нового `Rabbit`.

## 6. `models.Wolf` — волк (хищник)

Питается кроликами, размножается, при отсутствии добычи просто бродит и
теряет энергию на перемещение.

Поля: `visRange = 5` (зрение шире, чем у кролика — иначе волки не
успевали бы догонять более многочисленных кроликов), `currentMax` (лимит
популяции, по умолчанию 30, динамический), `currentDivideThreshold`
(порог размножения, по умолчанию 22, динамический).

**`act()`**:

1. Ищутся кролики в радиусе видимости (`look("Rabbit")`).
2. Если найдены — волк идёт к ближайшему (по пути, если кролик рядом,
   `move()` его съест).
3. Если кроликов не видно — случайное блуждание в одном из 4 направлений.
4. `finishTurn()` — та же логика, что у кролика: смерть при нуле энергии,
   размножение при достижении порога.

**`eat(Agent prey)` (переопределён)** — в отличие от базового поведения,
волк получает энергию жертвы *плюс бонус* `bonus = 3` за успешную охоту.
Это дополнительное поощрение хищничества, введённое для баланса (иначе
волкам постоянно не хватало энергии на перемещение и размножение).

`look()`, `near()`, `canDivide()`, `createChild()` устроены аналогично
`Rabbit`, но со своими радиусом видимости и лимитом популяции.

## 7. `models.Environment` — мир и цикл симуляции

Управляет сеткой, инициализацией начальной популяции, порядком выполнения
ходов и статистикой.

### Инициализация

Конструктор `Environment(range, num_P, num_R, num_W)` создаёт сетку
`range × range` и расставляет заданное число растений, кроликов и волков
(метод `placeAgents`) в случайные свободные клетки. Каждому агенту при
создании присваивается стартовая энергия базового значения (6 для
растений, 14 для кроликов, 22 для волков) со случайным «джиттером»
(`±2`) — это специально сделано, чтобы агенты не достигали порога
размножения синхронно всей популяцией разом (что вызывало резкие
демографические скачки и дестабилизацию системы).

Есть проверка: если суммарное число агентов больше числа клеток на поле —
бросается `IllegalArgumentException`.

### Главный цикл: `simulation()` (вызывается через публичный `step()`)

На каждом шаге:

1. Увеличивается счётчик шагов `stepCounter`.
2. **`updateLimits()`** — динамически пересчитывает лимиты популяции и
   пороги размножения для кроликов и волков **в зависимости от их
   текущей численности**:
   - Мало кроликов (< 30) → порог размножения ниже (14), лимит популяции
     выше (250) — кролики плодятся охотнее.
   - Кроликов много (≥ 80) → порог выше (20), лимит ниже (180) —
     размножение сдерживается.
   - Аналогичная логика для волков (пороги 5 / 12 особей).

   Это своего рода саморегуляция экосистемы: система «подкручивает»
   параметры видов в реальном времени, не давая ни одному виду вымереть
   или бесконтрольно расплодиться.
3. Делается **снимок (snapshot)** всех живых агентов в отдельный список
   *перед* тем, как кто-либо из них походит. Это важно: агенты во время
   хода изменяют саму сетку `field`, и если бы обход шёл прямо по
   двумерному массиву во время изменений, порядок и корректность ходов
   могли бы нарушиться (например, агент мог бы сходить дважды за шаг или
   съесть уже мёртвую цель). Снимок гарантирует, что за один вызов
   `simulation()` каждый агент, живший на начало хода, ходит ровно один
   раз.
4. Для каждого агента из снимка, если он всё ещё жив (мог быть съеден
   кем-то раньше в этом же шаге), вызывается `agent.act()`.

### Прочие методы

- **`count(String type)`** — считает число живых агентов заданного типа на
  поле (используется и для статистики в GUI, и для условий остановки).
- **`show()` / `showOne()` / `showMore()`** — консольная визуализация
  (текстовая карта из символов `*`/`T`/`X`) и циклы запуска без GUI;
  оставлены с ранних этапов разработки как отладочный/консольный вариант.
- **`getRange()`, `getStep()`** — геттеры для GUI.
- **`step()`** — публичная обёртка над `simulation()`, которую вызывает
  GUI на каждый тик.

## 8. GUI-слой (`gui` package)

### `Sprites`

Утилитный класс для загрузки PNG-спрайтов агентов (`plant.png`,
`rabbit.png`, `wolf.png`, `dirt.png`) из ресурсов classpath. Загруженные
изображения кэшируются в `HashMap`, чтобы не читать файл с диска повторно.
`getScaled()` дополнительно масштабирует картинку под нужный размер
клетки с билинейной интерполяцией. Если ресурс не найден — метод тихо
возвращает `null`, а вызывающий код (`WorldPanel`) в этом случае рисует
цветной прямоугольник-заглушку вместо спрайта.

### `WorldPanel`

`JPanel`, отвечающая за отрисовку сетки мира. В `paintComponent()`:

- Проходит по всем клеткам `world.field`.
- Под каждой клеткой сначала рисует «землю» (`dirt.png` или бежевый
  прямоугольник как запасной вариант).
- Если в клетке есть живой агент — поверх земли рисует его спрайт,
  выбранный по `a.getType()` (через `switch`). Если спрайт для этого типа
  не найден — рисуется пурпурный прямоугольник (чтобы визуально было
  заметно, что ресурс не подгрузился).
- Рисует тонкую серую сетку-обводку между клетками.

Метод `refresh()` просто вызывает `repaint()` — им пользуется
`SimulationFrame`, чтобы обновить картинку после каждого шага.

### `SimulationFrame`

Главное окно приложения (`JFrame`). Содержит:

- `WorldPanel` в центре.
- Панель управления снизу: кнопки **«Старт»**, **«Пауза»**, **«Шаг»**,
  ползунок скорости и лейблы со статистикой (номер шага, число растений,
  кроликов, волков).

**Логика кнопок:**

- **«Старт»** — если симуляция уже не запущена, поднимает флаг `running`,
  блокирует кнопку «Старт», разблокирует «Пауза» и запускает отдельный
  фоновый поток (`sim-loop`, daemon-поток), в котором крутится
  `gameLoop()`.
- **«Пауза»** — опускает флаг `running` (цикл в фоновом потоке сам
  завершится на следующей итерации) и возвращает кнопки в исходное
  состояние. Учитывает, что вызвана может быть как из потока интерфейса
  (EDT), так и из другого потока — если не EDT, обновление кнопок
  оборачивается в `SwingUtilities.invokeLater`.
- **«Шаг»** — выполняет один шаг симуляции синхронно (`doOneStep()`):
  вызывает `world.step()`, обновляет статистику и перерисовывает поле, а
  затем проверяет, не вымер ли кто-то (`checkExtinctionOnce()`).

**`gameLoop()`** — работает в отдельном потоке, пока `running == true`:

1. Вызывает `world.step()`.
2. Считывает текущую статистику (число растений/кроликов/волков, номер
   шага) — **до** передачи в UI-поток, чтобды не работать с изменяемым
   состоянием из чужого потока.
3. Через `SwingUtilities.invokeLater` обновляет лейблы и перерисовывает
   `WorldPanel` — вся работа с компонентами Swing выполняется строго в
   Event Dispatch Thread, как того требует сам Swing.
4. Проверяет вымирание любого из трёх видов; если кто-то вымер —
   останавливает цикл, возвращает кнопки в исходное состояние и
   показывает диалоговое окно `JOptionPane` с сообщением, на каком шаге
   это произошло. Флаг `alreadyStopped` защищает от повторного показа
   диалога.
5. Если никто не вымер — поток «засыпает» на время, вычисленное из
   положения ползунка скорости: `delay = 210 - speedSlider.getValue()`
   (диапазон слайдера 1–200, то есть задержка от ~10 мс до 209 мс за
   шаг — чем правее ползунок, тем быстрее идёт симуляция).

**`updateStats()`** — синхронно обновляет лейблы статистики (используется
при инициализации окна и после ручного шага).

**`checkExtinctionOnce()`** — то же самое, что проверка вымирания в
`gameLoop()`, но вызывается после одиночного шага по кнопке «Шаг».

### `Main`

Точка входа. В `SwingUtilities.invokeLater` (чтобы GUI создавался в
правильном потоке — EDT) создаёт `Environment` размером 30×30 со
стартовыми популяциями 300 растений / 80 кроликов / 12 волков и
открывает `SimulationFrame` с размером клетки 20 пикселей.

Закомментированный код вверху файла — это более ранняя, консольная версия
`main`, оставленная для истории/отладки.

## 9. Механика баланса экосистемы (сводка)

Коротко о том, что удерживает систему от вымирания видов:

1. **Энергетический джиттер при старте** — агенты не размножаются
   синхронно всей популяцией разом.
2. **Ограничение плотности растений** (`max_destiny = 0.3`) — растения не
   заполоняют всё поле и не «душат» пространство для передвижения других
   агентов.
3. **Глобальное размножение растений** (в любую свободную клетку, а не
   только по соседству) — предотвращает локальное истощение зон, где уже
   растёт много травы.
4. **Приоритет «угроза → еда → блуждание»** у кролика — не даёт кроликам
   гарантированно вымирать от хищников, пока они ищут еду.
5. **Бонус энергии волку за охоту** — компенсирует высокую стоимость
   перемещения и погони, не давая волкам вымирать от голода даже при
   успешной охоте.
6. **Динамические пороги размножения и лимиты популяции**
   (`Environment.updateLimits()`) — при малой численности вида условия
   размножения смягчаются, при большой — ужесточаются, что действует как
   само-стабилизирующийся механизм (аналог экологической ёмкости среды).
7. **Snapshot-обход** в `simulation()` — гарантирует детерминированную и
   корректную последовательность ходов за шаг, без двойных ходов или
   гонок состояний.

## 10. Как запустить

1. Собрать проект (пакеты `models` и `gui`, плюс `Main.java` в корне
   classpath).
2. Убедиться, что в classpath доступны ресурсы `plant.png`, `rabbit.png`,
   `wolf.png`, `dirt.png` (используются `Sprites`; при их отсутствии GUI
   всё равно работает, просто рисует цветные прямоугольники-заглушки).
3. Запустить `Main.main()`.
4. В открывшемся окне:
   - **«Старт»** — запустить непрерывную симуляцию;
   - **«Пауза»** — остановить;
   - **«Шаг»** — выполнить ровно один ход вручную;
   - ползунком **«Скорость»** — регулировать темп симуляции.
5. Симуляция автоматически остановится и покажет диалог, если вымрет хотя
   бы один из трёх видов.
